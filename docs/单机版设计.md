# SCOUT 单机版（H5）· 实施设计文档

> 桌游 **SCOUT**（设计：Kei Kajino / 出版：Oink Games）的粉丝单机网页版。
> 玩家 1 人 + 2~4 个 AI，模拟 3/4/5 人局；纯前端、可离线（PWA）。
> 本文档为最终实施记录，与 `src/` 代码一一对应。

---

## 1. 规则依据（已逐条核实）

以官方英文规则书 v3.0（One More Game 出版版，PDF 原文逐页读取）为准，并用 Oink 官网的
国际版勘误图（errata）交叉确认。与流传的简化摘要不同处已按官方文本执行：

| 规则点 | 官方结论 | 代码位置 |
| --- | --- | --- |
| 牌组 | 45 张 = 1~10 两两数字对，全牌唯一 | `core/deck.ts` |
| 3 人局 | 去掉**所有**含 10 的牌（36 张，每人 12） | `deckForPlayerCount` |
| 4 人局 | 只去掉 9/10 一张（44 张，每人 11） | 同上 |
| 5 人局 | 全用（45 张，每人 9） | 同上 |
| 朝向 | 洗牌时正反面随机；开局可**整手旋转 180°** 一次 | `dealHands` / `FlipDialog.vue` |
| 首手 | 桌上无牌型时可出任意合法牌型（含单张） | `rules.legalShows` |
| 表演 | 手牌**相邻连续一块**：同数 / 连续（升序降序皆可）/ 单张 | `rules.classify` |
| 压过 | ①张数多者强 ②等张数同数＞顺子 ③再比最低数字，**严格更大**（相等不行） | `rules.beatsCombo` |
| 侦察 | 从当前牌型**端点**取 1 张，任意朝向插入手牌任意位置；**牌型主人 +1 金币**，牌型保留 | `engine.doScout` |
| 侦察后牌型强度 | 取走一张后按剩余牌**重新判定**（如 9·9·9 被拿 1 张后变为 9·9） | `engine.doScout` |
| 双动 | 每轮 1 枚标记：侦察后**立刻**表演（压过剩余牌型） | `engine.applyAction('doubleAction')` |
| 轮结束 i | 有人打光手牌 | `engine.applyAction` |
| 轮结束 ii | 其他玩家全部只侦察、回到牌型主人前 → 结束，**主人免剩牌罚分** | `engine.doScout` 计数 |
| 计分 | 收来的暗牌 +1/张、金币 +1/枚、剩牌 −1/张；被压的牌归**出牌者** | `engine.endRound` / `doShow` |
| 轮次 | 局数 = 人数；下一轮首出者向左轮换、重发全牌 | `engine.startNextRound` |
| 终局 | 总分最高者胜，平分共享胜利 | `GameOverPanel.vue` |

## 2. 架构

```
src/
├─ core/            # 纯 TS 规则内核：无 DOM / 无 Vue / 无网络，可整体搬上服务端做权威校验
│  ├─ types.ts      # Card / Combo / GameState / GameAction / GameEvent（UI↔引擎契约）
│  ├─ rng.ts        # mulberry32 可复现洗牌（seed 入状态，可复盘）
│  ├─ deck.ts       # 牌组构成 / 按人数去牌 / 发牌
│  ├─ rules.ts      # 纯函数：classify / beatsCombo / legalShows / structureScore
│  ├─ engine.ts     # applyAction 状态机：先校验后应用，非法动作抛 RuleError
│  ├─ metrics.ts    # 手牌结构指标：B(最少出牌数)/L(最长组)/P(连接潜力)/N(剩牌)
│  └─ ai/
│     ├─ index.ts   # AiStrategy 接口（可插拔）
│     ├─ greedy.ts  # 学徒：单步手牌结构优化（只看自己）
│     ├─ planner.ts # 艺人：即时收益贪心 G(a)=减牌+收牌+结构+预计筹码−给对手−结束风险
│     └─ oracle.ts  # 团长：一圈全信息前瞻（推演所有对手的演出/挖角/双动回应）
├─ stores/          # Pinia：core 状态镜像给 UI；UI 只读镜像 + 发意图（dispatch）
├─ ui/
│  ├─ views/        # Home / Game / Rules / Settings
│  ├─ components/   # CardFace / CardBack / ChipIcon / SeatPanel / ActiveSetPanel /
│  │                # HandArea / ActionBar / ScoutEndOverlay / FlipDialog /
│  │                # RoundResultPanel / GameOverPanel
│  └─ art.ts        # 数字色带 / 表演者名池 / 节目图标 path
├─ theme/           # tokens.css（design tokens）/ fonts.css / base.css
└─ assets/fonts/    # Alfa Slab One（卡面数字）/ Rye（标题），本地 woff2 离线可用
```

**解耦纪律**：UI 永远不直接改 `GameState`，只能 `dispatch(action)`；引擎校验失败抛
`RuleError`，store 捕获后转 toast。联机升级时把 `core/` + `applyAction` 原样搬到服务端即可。

## 3. 美术还原（对照 Oink 国际版实物/官网图）

- **卡面**：白边 + 双色波浪底（两色即这张牌两端数字的色带色）、左上超大数字（Alfa Slab
  One + 硬边阴影）、**正下方黑色圆角小牌印另一端数字**、顶部居中表演者名、底部倒印同一
  名字（翻转后可读，与实体牌一致）、右侧马戏节目线稿图标。
- **牌背**：紫色放射纹 + 大 S。
- **数字 1~10**：暖→冷色带（色盲模式下降饱和，数字始终是主信息）。
- **桌面**：深绿绒布 + 木纹桌沿；当前行动者聚光灯描边 + AI 思考脉冲。
- **筹码**：S 金币（侦察补偿/VP）与星形分数筹码。
- **动效**：CSS transition + spring easing（`--ease-pop`），时长 160~420ms，
  `prefers-reduced-motion` 与设置里的动画速度均可降级。

## 4. 交互设计要点

**响应式双版式**（`ui/composables/useViewport.ts`，断点 900px）：
- **竖版（手机）**：座位纵列在上、中央牌区、手牌底部重叠扇形（12 张全露一行）、单手可玩；
- **横版（桌面 / 平板横屏）**：座位一排居中、中央舞台与手牌区限宽（920~1100px）放大居中，
  手牌牌宽 84px 且几乎全露，操作条三分横排放大。

- **手牌**：重叠扇形自适应（12 张 360px 宽全露一行）；无选区时合法块自动描边
  （顺子青色 / 同数紫色）；「点首张 + 点末张」框选，徽标实时给出 ✓/✗ 与原因；
  顶部 🔒 提示顺序锁定。
- **侦察**：浮层选牌型端点（多张时两端可选、单张只有一端）→ 手牌上方出现编号缝隙条 +
  翻转开关 → 插入完成。牌型主人即时 +1 金币。
- **双动**：侦察后手牌区切换为**插入后预览**（与引擎校验下标一致），表演要压的目标自动
  变为「拿走一张后的剩余牌型」；按钮文案变为「双动 · 表演」。
- **结算**：逐列展示 收牌/金币/剩牌罚分（条件 ii 达成者显示「免罚」）/本轮/总分；
  终局排名榜 + 再来一局。

## 5. AI 三层难度（单调包含）

```
手牌结构优化（学徒） ⊂ 即时收益贪心（艺人） ⊂ 一圈全信息前瞻（团长）
```

共用指标（`core/metrics.ts`）：
- **B**：清空手牌至少需要的合法连续牌组数（相邻段划分 DP，越小越好）
- **L**：最长连续/同数牌组
- **P**：潜在连接能力 = 对子核心 + 桥位（隔一张成三连）+ 可成长二连 + 端点延伸位
- **I**：孤张数（与左右邻牌都不相连，四人局起权重升高，五人局为第一目标）
- **N**：剩余手牌数

| 档位 | 决策范围 | 要点 |
| --- | --- | --- |
| 学徒 | 只看行动后自己的手牌 | max(ΔB, ΔP, L) − 新增手牌；打孤张不拆链；挖角须降 B / 成三连 / 桥接两组才值 1 分成本；同收益先出较短较弱组；保留 ≥2 终结组 |
| 艺人 | + 即时得分与风险 | G(a) = 减牌 + 收牌 + 结构改善 + 预计挖角筹码 − 给对手筹码 − 结束风险；能出完立即演出；用最小组合压制；对手 ≤3 张时减牌优先；双动用于桥牌 / 吃端点后反压 / 防守 |
| 团长 | + 假设知晓各家手牌，推演一整圈 | 逐个模拟对手的直接演出、挖角端点选择、双动反制；全员压不过的强组直接封轮（免罚）；牌型被挖空 → 桌面清空、下家必须演出的边界已精确处理；4/5 人局按「减牌 + 收牌」稳健线路加权 |

人数差异（按规格实现）：
- **三人局**：培养「两张以上终结组」，找全员挖角封轮；
- **四人局**：先减孤张、控节奏，确认安全才用三张以上大组封轮；
- **五人局**：减牌竞速而非封轮竞赛——消灭孤张 > 降 B > 增 L；对子就是合格的减牌单位；
  封轮需要 ≥4 张组（3 张会被前三名玩家挖空，第四名获得自由演出）；挖角筹码期望按人数
  衰减（×1 / ×0.85 / ×0.65）；双动用于维持节奏。

自博弈基准（多种子全程对局，`scripts/benchmark.ts` 可复跑）：

```
3人局：学徒 胜者均分 16.8 < 艺人 24.2 < 团长 29.8（团长分差最小 13.3）
4人局：学徒 23.4 < 艺人 39.0 < 团长 41.3
5人局：学徒 20.5 < 艺人 35.1 < 团长 39.0
回合结束方式：三人局封轮为主（50~67%）；四人局以打光为主（封轮 5~23%）；
             五人局几乎全靠打光（封轮 0~4%）——与规格的 94.9%/5.1% 同量级
```

> 注：早期版本的「回合结束方式比例」因「最后一张 Active Set 被挖角 → 桌面清空」的边界
> 漏判而失真，本文数值为边界修正后重测；策略强弱顺序不变，三人局封轮价值比旧结论更高。

## 6. 质量验证

- **Vitest 33 项全过**：牌组构成（45/36/44 张）、牌型分类（含降序顺子）、比较规则
  （张数→类型→最低数字，相等不可出）、合法枚举、引擎校验（回合/归属/双动标记）、挖角
  细节（金币、强度更新、拿空牌型、条件 ii 免罚）、计分公式、多轮推进、**多种子×3/4/5
  人局全程模拟**（无死锁 + 牌数守恒 36/44/45）、人类参与的 4 人局全程。
- **vue-tsc 全量类型检查 0 错误**。
- **浏览器实机冒烟**：主页 → 开局翻转 → 演出/挖角/双动全流程 → 金币与收牌归属 →
  AI 三档混战；桌面视口 390px 竖屏单手可玩。
- `npm run build` 产出 PWA（manifest + SW precache，离线可玩）。

## 7. 运行

```bash
npm install
npm run dev        # 开发（http://localhost:5173）
npm test           # Vitest
npm run build      # 产出 dist/（PWA）
npm run preview    # 预览构建产物
```

## 8. 已知边界与后续

- 2 人局官方为变体规则（3 筹码、无双动），本版按设计目标只做 3~5 人。
- 音效开关已留（Settings），音源未内置。
- AI「团长」档为一圈推演（对手采用二档决策器建模）；可继续加深为多圈/搜索/MCTS，接口已留。
- 联机化：`core/` 直接上 Node 权威服，UI 的 store 改为 WS 事件镜像即可。
